title: Glossary
description: Learn about the key concepts and tools used throughout Qonstruct.
------------------------------------------------------------------------------

This glossary explains some of the key concepts, models, and reusable components used throughout Qonstruct.

### Block

A **Block** is a reusable building element within a quantum low-code model. Blocks encapsulate a specific operation and can be combined with other blocks to create more complex models.

### Domain Block

A **Domain Block** is a block defined by a domain profile. It represents a concept of an application domain, such as a relation or a schema, under a domain-specific name, icon, and description. Each domain block belongs to a palette category and defines its own inputs, outputs, properties, and constraints, as well as a mapping to the standard Qonstruct elements that implement it.

Models that contain domain blocks are executed on Camunda 8.

### Domain Profile

A **Domain Profile** is a collection of domain blocks tailored to a specific application domain. When a domain profile is selected in the Experience Mode, it replaces the standard palette with its domain blocks, so that users can model in the terminology of their domain without detailed knowledge of quantum computing.

Domain profiles are created and managed with **Manage Domain Profiles** in the toolbar, stored as JSON files, and can be loaded from a shared profile repository.

### Low-Code Model

A **Low-Code Model** is a visual representation of a quantum application that can be created with minimal hand-written code. Users can build and configure models using graphical elements, properties, and predefined templates.

### Placeholder

A **Placeholder** represents a value that is not known at design time. Placeholders allow a model to be created without specifying all required values in advance.

When a model containing placeholders is transformed into a workflow, the corresponding values can be provided during **runtime**. This allows the same model to be reused with different input values without modifying the model itself.

### Qonstruct

**Qonstruct** is a visual modeling and execution environment for quantum applications. It enables users to build quantum applications using graphical models rather than implementing every component manually.

### Quantum Circuit

A **Quantum Circuit** is a representation of a quantum computation. It describes how quantum bits (qubits) are initialized, manipulated through quantum gates, and measured to produce results.

### Templates

**Templates** are ready-to-use models. They can be customized to match specific requirements, reducing the time and effort needed to build a model from scratch.

### Workflow

A **Workflow** refers to a workflow modeled using **Business Process Model and Notation (BPMN)**. BPMN provides a standardized graphical notation for describing business processes, including tasks, events, decisions, and the flow between them.
