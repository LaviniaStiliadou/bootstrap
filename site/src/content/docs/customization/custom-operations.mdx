## Overview

The **Custom Quantum Operator** and the **Custom Classical Operator** let you add your own operations to a model. Each operator gets an implementation, for example a Python file, and any number of classical and quantum inputs and outputs. When the model is transformed, the operator becomes a task in the generated workflow, which is then deployed and executed on [Camunda]([[docsref:/integrations-services/camunda-engine]]).

For a full list of the operator properties and validation rules, see [Custom Operators]([[docsref:/getting-started/modeling-language#custom-operators]]) in the modeling language.

## Writing the implementation

The inputs and outputs of a Python implementation are declared with comment annotations at the top of the file:

```python
# @input a
# @output result
result = 2 * a
```

- `# @input <name>` declares a variable that receives the value of a connected input.
- `# @output <name>` declares the variable whose value is returned as the output of the operator.

In this example, the operator takes the number `a`, doubles it, and returns it as `result`.

## Prerequisites

Executing a model with custom operations requires the workflow services and the LEQO backend.

1. Start the ICSE Docker setup by following the instructions in the [QuantME Use Cases repository](https://github.com/UST-QuAntiL/QuantME-UseCases/tree/fix/2025-icse-docker/2025-icse). Use the [Docker Compose file](#docker-compose-file) below instead of the one in the repository. It leaves out services that aren't required.
2. Set `PUBLIC_HOSTNAME` to the hostname or IP address of your Docker engine. Don't use `localhost`.
3. Start the [LEQO backend](https://github.com/LEQO-Framework/leqo-backend):

   ```bash
   docker compose -f compose-dev.yaml up --build
   ```

## Running the example

1. Set your IP address in the `.env` file of the low-code-modeler repository. On Windows, you can find your IP address by running `ipconfig` in the command prompt.
2. Start Qonstruct and open the configuration window. Check that your IP address has been loaded correctly and that the Camunda endpoint contains the correct IP address.
3. Load the [example model](#example-model) below, or your own model with a custom operation.
4. Transform the model by clicking **Model Transformation**.
5. Open **History** and click **Deploy Workflow**. Wait until the green confirmation message *Workflow is deployed on Camunda* appears.
6. Open Camunda and log in with the following credentials:
   - Username: `demo`
   - Password: `demo`
7. Click **Start Process** and select `process_workflow_process_no_placeholder`. Enter your IP address again where required.
8. Click the home icon in the upper-right corner and select **Cockpit**. Then, open the process.
9. Select the process instance and check the `result` variable. It should contain the final computed value. In the example model, the input is `2`, so `result` is `4`.
