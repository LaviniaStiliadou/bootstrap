## Overview

A custom template is a model that you saved for reuse. It appears in the palette under **Templates → User Templates**, next to the standard templates. When you drag it onto the canvas, its nodes and connections are added as a complete model, which you can then adapt.

Use custom templates for building blocks you need often, such as a state preparation followed by a fixed sequence of gates, or a complete algorithm configured for your problem.

## Saving a model as a template

1. Build the model on the canvas.
2. Click an empty area of the canvas. The right panel now shows the model **metadata**.
3. Enter a **name** and a **description**. They become the name and the description of the template in the palette. You can also set a version and an author.
4. In the toolbar, open the **Save Diagram** menu and choose **Save as Template**.

The template is added to the palette immediately under **Templates → User Templates**. It stores the nodes, the connections, the viewport and the metadata of the model.

> **Note:** Templates are saved in the local storage of your browser. They are available in every model you open in this browser, but not in other browsers or on other computers. To share them, export them as described below.

## Using a template

Drag the template from **Templates → User Templates** onto the canvas, like any other element.

## Managing templates

Click **Manage Templates** in the toolbar to open the **Manage User Templates** dialog. There you can:

| Action      | Description                                                                                         |
| ----------- | --------------------------------------------------------------------------------------------------- |
| Search      | Filter the templates by name.                                                                       |
| Edit        | Change the **name**, **author** and **description** of a template.                                  |
| Icon        | Upload an image to use as the palette icon of the template.                                          |
| **Export**  | Download the template as `template_<id>.json`, for example to share it or keep it in a repository. |
| **Delete**  | Remove the template.                                                                                 |
| **Import**  | Load one or several template files. A file may contain one template or a list of templates.         |

Click **Save** to apply your changes. Closing the dialog without saving discards them.

## Template file format

An exported template is a JSON file with this structure:

```json
{
  "id": "flow-1760183040000",
  "label": "Custom Template-1760183040000",
  "type": "Templates",
  "name": "My Bell Pair",
  "description": "Prepares a Bell pair and measures it.",
  "icon": "QAOA.png",
  "completionGuaranteed": true,
  "compactOptions": [true, false],
  "timestamp": "2026-10-11T12:24:00.000Z",
  "flowData": {
    "nodes": [],
    "edges": [],
    "viewport": { "x": 0, "y": 0, "zoom": 1 },
    "metadata": { "name": "My Bell Pair", "description": "Prepares a Bell pair and measures it." }
  }
}
```

When you import a file, each template is checked:

- `id`, `name`, `description`, `icon` and `label` must be strings, and `completionGuaranteed` must be a boolean;
- `compactOptions` must be present;
- `type` must be `"Templates"`, and `label` must start with `Custom Template`;
- `flowData` must contain a `nodes` and an `edges` array.

Invalid files and templates whose `id` already exists are skipped. A message tells you how many templates were imported and which files were skipped.
