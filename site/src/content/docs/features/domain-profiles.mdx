## Overview

A domain profile is a palette tailored to an application domain. It consists of domain blocks, which represent concepts of the domain under their own name, icon, and description. Each domain block is mapped to the standard Qonstruct elements that implement it, so users can model in the terminology of their domain.

Models that contain domain blocks are executed on [Camunda 8]([[docsref:/integrations-services/camunda-engine]]).

## Selecting a domain profile

1. Open the **Experience Mode** panel in the top-left corner of the canvas.
2. Select a profile under **Domain Profile**.

The palette then shows the domain blocks of the profile instead of the standard elements. Select **None** to return to the standard palette. See [Experience Mode](./experience-mode#domain-profile).

## Managing domain profiles

Open **Manage Domain Profiles** in the toolbar. The dialog has two tabs:

- **Saved Profiles** lists all profiles. For each profile you can **Edit**, **Duplicate**, **Export**, or **Delete** it.
- **Create Profile** (or **Edit Profile** for an existing one) lets you name the profile and define its domain blocks.

To create a profile:

1. Open the **Create Profile** tab and enter a name.
2. Click **Add Domain Block** for every block of the domain and configure it (see [Domain blocks](#domain-blocks)). Blocks can be reordered by dragging.
3. Click **Save Profile**.

If a profile with the same name already exists, Qonstruct offers to save it under a versioned name instead.

Profiles can also be shared as JSON files with **Export Profile** and **Import Profile**.

## Domain blocks

Every domain block is configured with the following fields:

| Field           | Description                                                                                                    |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| **Name**        | The name of the block in the palette and on the canvas.                                                        |
| **Icon**        | The icon of the block.                                                                                         |
| **Category**    | The palette category the block appears in, for example a data type, **Quantum Operators**, or **Classical Operators**. |
| **Inputs**      | The input ports of the block, each with a name, a type, and whether it is optional.                            |
| **Outputs**     | The output ports of the block, each with a name, a type, and whether it is optional.                           |
| **Properties**  | Values the user sets on the block, each with a name, a type, and whether it is required.                       |
| **Constraints** | Conditions on a property, consisting of the property, a comparison (`==`, `!=`, `<`, `>`, `<=`, `>=`), and a value. |
| **Mapping**     | The standard elements the block is mapped to. A mapping can combine several elements, shown as `A + B`, and a block can have several mappings. |

Only blocks in the **Quantum Operators** category can mix quantum and classical ports. All other blocks use classical ports. Input and output names of a block must be unique.

## Loading profiles from a repository

Qonstruct can load domain profiles directly from a shared repository. To enable this, set the following environment variable to the raw base URL of a publicly accessible repository:

```env
VITE_DOMAIN_PROFILES_URL=https://raw.githubusercontent.com/<owner>/<repo>/main
```

Once configured, the **Domain Profile** dialog provides a **Load from Repository** option. Select a domain and revision to load the corresponding profile into Qonstruct.

If `VITE_DOMAIN_PROFILES_URL` isn't configured, repository-based domain profiles are disabled and the option is hidden.

### Repository structure

The repository is a static file tree and doesn't require a dedicated backend:

```text
index.json
<directory>/<version>.json
```

The `index.json` file describes the available domains and revisions:

```json
{
  "domains": [
    {
      "name": "Example Domain",
      "directory": "example",
      "versions": ["1.0.0", "1.1.0"],
      "latest": "1.1.0"
    }
  ]
}
```

Each `<version>.json` file contains the corresponding domain profile, including its blocks grouped by category.

The repository can be hosted using:

- GitHub Raw
- GitHub Pages
- Another raw Git hosting service
- A static file server
