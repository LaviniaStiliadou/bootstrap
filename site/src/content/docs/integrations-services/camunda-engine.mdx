---------

Qonstruct uses Camunda as its workflow engine. Depending on the requirements of the domain and the capabilities required by the generated workflow, Qonstruct can target either [Camunda 7](https://docs.camunda.org/manual/7.24/) or [Camunda 8](https://docs.camunda.io/).

The choice of engine is determined by the characteristics of the workflow rather than by the modeling interface itself.

## Engine selection

The backend analyses the generated workflow and determines which Camunda runtime is required.

The basic decision is:

```text
                    Qonstruct Workflow
                           │
                           ▼
                 Does the workflow
                 require agentic /
              non-deterministic logic?
                     /           \
                   yes            no
                   │               │
                   ▼               ▼
              Camunda 8        Camunda 7
```

### Camunda 8

Camunda 8 is used when the low-code model contains domain blocks since it provides dedicated capabilities for integrating AI agents into BPMN-based workflows. Its agentic orchestration allows deterministic BPMN processes to be combined with AI-driven decisions and agentic behaviour.

In particular, Camunda 8 supports agentic subprocesses based on ad-hoc subprocesses. These allow an AI agent to dynamically select and execute tools represented by BPMN activities rather than following only a predefined sequence.

For more information, see the [Camunda 8 documentation](https://docs.camunda.io/) and the [Camunda 8 documentation on agentic orchestration](https://docs.camunda.io/docs/components/agentic-orchestration/agentic-orchestration-overview/).

## Camunda 7

If the generated workflow does not require agentic subprocesses or Camunda 8-specific capabilities, Qonstruct can target Camunda 7.

This allows conventional, deterministic process models to be executed without introducing the additional runtime capabilities required for agentic orchestration.

The workflow can therefore remain based on explicitly defined process paths, tasks, events, and decisions.

For more information, see the [Camunda 7 documentation](https://docs.camunda.org/manual/latest/).
