## Overview

The toolbar at the top of the modeler groups its buttons into sections. Hover over a button to see its name.

| Section                     | Buttons                                                                   |
| --------------------------- | ------------------------------------------------------------------------- |
| Test Flows                  | Generate Test Flows (only if enabled)                                     |
| Start                       | Open New Diagram, Open Diagram, Save Diagram, Upload to GitHub, Configuration |
| User Templates              | Template Library                                                          |
| Domain Profiles             | Profile Manager                                                           |
| AI Features                 | Algorithm Detection, Model Generation                                     |
| Transformation & Execution  | Model Transformation, History                                             |
| Help                        | Help                                                                      |

## Test Flows

### Generate Test Flows

Opens a dialog that generates erroneous test models for the selected elements, based on an error taxonomy of data and type errors, parameter and configuration errors, and flow errors. Each generated model is validated, and optionally compiled by the backend. The dialog shows a report with the generated error, the affected nodes, the expected behavior and the platform response, and lets you download the models and the report as a ZIP file.

The button is only shown if `VITE_ENABLE_NODE_TESTING=true` is set (see [Configuration](./configuration)).

## Start

### Open New Diagram

Clears the canvas and starts a new model. If the canvas isn't empty, you are asked to confirm first, because unsaved changes are lost.

### Open Diagram

A menu with three entries:

| Entry                     | Effect                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Open Diagram**          | Opens a model saved as a JSON file.                                                                  |
| **Open Pattern Solution** | Opens the **Select Existing Low-Code Solution** dialog to load a model that is linked to a pattern in the Pattern Atlas. |
| **Open OpenQASM**         | Opens an OpenQASM file and converts it into a model (see [OpenQASM Editor](./openqasm-editor)).       |

### Save Diagram

A menu with three entries:

| Entry                | Effect                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Save Diagram**     | Downloads the model as a JSON file, named after the model name and id in the metadata.                        |
| **Save as SVG**      | Downloads an image of the canvas as `reactflow-diagram.svg`.                                                   |
| **Save as Template** | Saves the model as a custom template in the palette (see [Custom Templates](./custom-templates)).              |

### Upload to GitHub

A menu with two entries:

| Entry                       | Effect                                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Upload File**             | Uploads the model as a JSON file to the GitHub repository from the configuration.                         |
| **Upload Pattern Solution** | Opens the **Select Pattern** dialog to link the model as a solution to a pattern of the Pattern Atlas.   |

The repository owner, name, branch and token are set in the **GitHub** tab of the configuration or in `.env`.

### Configuration

Opens the **Configuration** dialog with the editor settings, the GitHub settings and the endpoints of the connected services (see [Configuration](./configuration)).

## User Templates

### Template Library

Opens the **Manage User Templates** dialog. There you can search, edit, export, import and delete your custom templates (see [Custom Templates](./custom-templates)).

## Domain Profiles

### Profile Manager

Opens the domain profile editor. A domain profile is a palette tailored to an application domain, with its own elements and their mapping to standard elements. You can create, edit, duplicate and load profiles, and select the active profile in the [Experience Mode](./experience-mode).

## AI Features

### Algorithm Detection

Detects from a natural language description of your problem which algorithm, for example QAOA, Grover's algorithm or the QFT, and therefore which low-code model can be used to solve it. It requires an OpenAI token (`VITE_OPENAI_TOKEN` or the **Low-Code Endpoints** tab of the configuration).

### Model Generation

Opens the **Generate Model with AI** dialog. Describe the model you need in natural language. If the description lacks values, such as the problem type or a constant value, the **Add Required Values** step asks for them. The generated model is placed on the canvas, and the generation job is listed in the **History** with its pipeline report.

Model Generation uses the generation service (`api` and `worker` in `docker-compose.yml`) at `http://localhost:3000`, which needs a `MISTRAL_TOKEN` in its `.env`.

## Transformation & Execution

### Model Transformation

Transforms the model into a quantum circuit or a workflow:

1. The model is validated. The **Validation** dialog lists all errors and warnings with the node id and node type. You can only continue if there are no errors.
2. Choose the **Compilation Target**: **OpenQASM3** for a quantum circuit, or **Workflow** for models with classical or machine learning steps. OpenQASM3 isn't available if the model contains placeholders or workflow elements.
3. The model is sent to the backend. The result is added to the **History**.

### History

Opens the **History** dialog with all transformations and generated models. For each entry it shows the name, description, creation time and status, and lets you download the model file and the result file. **Execute** runs the result: a workflow is deployed to and started in Camunda, and an OpenQASM circuit is executed with Qunicorn. Programs without measurements are marked, because executing them gives no meaningful result.

## Help

### Help

Starts a guided tour through the modeler that explains the palette, the canvas, the panels and the toolbar.

## Canvas controls

These controls aren't part of the toolbar but are placed on the canvas:

| Control                | Position                    | Effect                                                                    |
| ---------------------- | --------------------------- | ------------------------------------------------------------------------- |
| Experience Mode        | Top left                    | Experience settings (see [Experience Mode](./experience-mode)).           |
| Group selection        | Bottom left, above the zoom controls | Lasso for creating groups (see [Grouping](./grouping)).           |
| Zoom and fit controls  | Bottom left                 | Zoom in and out, and fit the model into the view.                         |
